# OpenAPI

Light.PortableResults documents its responses in OpenAPI documents generated by Microsoft.AspNetCore.OpenApi: success bodies with or without metadata, Problem Details, and validation problems with discriminated error schemas and examples. A Roslyn source generator derives the validation error contract of an endpoint directly from your validator. This page covers registration, documenting endpoints, reusable error contracts, source generation, custom checks, and the reference of all generator diagnostics.

**Packages:** `Light.PortableResults.AspNetCore.OpenApi` (namespace `Light.PortableResults.AspNetCore.OpenApi`); `Light.PortableResults.Validation.OpenApi` (namespace `Light.PortableResults.Validation.OpenApi`) for built-in validation error contracts and the source generator.

OpenAPI support is opt-in and does not change runtime serialization. The package contributes endpoint metadata and a document transformer that understands `LightResult<T>` and `LightActionResult<T>`.

## Registration

```csharp
using Light.PortableResults.AspNetCore.MinimalApis;
using Light.PortableResults.AspNetCore.OpenApi;
using Light.PortableResults.Validation.OpenApi;

builder.Services
       .AddOpenApi()
       .AddPortableResultsForMinimalApis()
       .AddPortableResultsOpenApi(contracts => contracts.RegisterBuiltInValidationErrors());
```

Use `AddPortableResultsForMvc()` for MVC applications. `AddPortableResultsOpenApi` registers the document transformer for all OpenAPI documents. It reads the registered `PortableResultsHttpWriteOptions`, so the documented shapes follow your `ValidationProblemSerializationFormat` and `MetadataSerializationMode` unless an endpoint overrides them. `RegisterBuiltInValidationErrors()` registers schemas for all built-in validation error codes from `Light.PortableResults.Validation`.

## Documenting endpoints

Minimal APIs expose three helpers:

- `ProducesPortableSuccessResponse<TValue>(...)` — documents the success response (bare `TValue` or `{ value, metadata }` depending on `MetadataSerializationMode`).
- `ProducesPortableProblem(...)` — documents a non-validation failure response (`500` by default).
- `ProducesPortableValidationProblem(...)` — documents a validation failure (`400` by default, or `422`), selecting the rich or ASP.NET Core-compatible envelope shape according to the configured or overridden format.

MVC exposes matching attributes: `[ProducesPortableSuccessResponse<TValue>]`, `[ProducesPortableProblem]`, and `[ProducesPortableValidationProblem]`. All of them accept a status code and a content type.

```csharp
app.MapPut("/api/movieRatings", async (MovieRatingDto dto, AddMovieRatingService service) =>
    {
        var result = await service.AddMovieRatingAsync(dto);
        return result.ToMinimalApiResult();
    })
   .ProducesPortableSuccessResponse<MovieRating>()
   .ProducesPortableValidationProblem(
        configure: x =>
            x.UseFormat(ValidationProblemSerializationFormat.Rich)
             .WithErrorCodes(ValidationErrorCodes.NotEmpty, ValidationErrorCodes.LengthInRange)
             .WithInRangeError<int>()
    )
   .ProducesPortableProblem();
```

The `configure` callbacks receive a builder:

| Builder | Methods |
| --- | --- |
| `PortableSuccessResponseOpenApiBuilder` | `WithMetadata<TMetadata>()`, `UseMetadataSerializationMode(mode)` |
| `PortableProblemOpenApiBuilder` | `WithMetadata<TMetadata>()`, `WithErrorCodes(...)`, `WithErrorMetadata<TMetadata>(code)`, `WithErrorMetadata(code, schemaFactory)`, `WithErrorExample(code, target, message, metadata)`, `AllowUnknownErrorCodes()` |
| `PortableValidationProblemOpenApiBuilder` | everything of `PortableProblemOpenApiBuilder`, plus `UseFormat(format)` |

`WithMetadata<TMetadata>()` documents the top-level `metadata` property. Documenting success metadata while `MetadataSerializationMode` is `ErrorsOnly` throws, because metadata is not part of that wire format. The MVC attributes expose the same settings as properties: `TopLevelMetadataType`, `ErrorCodes`, `AllowUnknownErrorCodes`, `Format`, and `MetadataSerializationMode`.

### Narrowing error schemas

`WithErrorCodes(...)`, `WithErrorMetadata<TMetadata>(code)`, and typed helpers like `WithInRangeError<T>()` narrow error items exhaustively once you document at least one code. The generated schema becomes a `oneOf` discriminated by `code`.

If an endpoint can emit additional codes that cannot be enumerated at build time, opt out with `AllowUnknownErrorCodes()` (Minimal APIs) or `AllowUnknownErrorCodes = true` (MVC attributes). The schema then falls back to a non-exhaustive `anyOf` shape while still documenting the known variants.

`Light.PortableResults.Validation.OpenApi` adds typed helpers for the rules whose metadata type depends on the checked type: `WithEqualToError<T>()`, `WithNotEqualToError<T>()`, `WithGreaterThanError<T>()`, `WithGreaterThanOrEqualToError<T>()`, `WithLessThanError<T>()`, `WithLessThanOrEqualToError<T>()`, `WithInRangeError<T>()`, `WithNotInRangeError<T>()`, and `WithExclusiveRangeError<T>()`.

### Reusable error code contracts

Register per-error-code metadata contracts once in DI, then opt specific endpoints into them:

```csharp
builder.Services.AddPortableResultsOpenApi(contracts =>
{
    contracts.ForCode<VersionMismatchMetadata>("VersionMismatch");
    contracts.ForCode<InsufficientFundsMetadata>("InsufficientFunds");
});

app.MapPut("/api/movieRatings", handler)
   .ProducesPortableValidationProblem(
        configure: x => x.WithErrorCodes("VersionMismatch")
    );
```

`ErrorMetadataContractsBuilder.ForCode` accepts a CLR type (`ForCode<TMetadata>(code)` or `ForCode(code, type)`), an OpenAPI schema factory (`ForCode(code, specVersion => new OpenApiSchema { ... }, schemaId)`), or nothing for codes without metadata (`ForCode(code)`). Every code passed to `WithErrorCodes` must be registered this way; otherwise, generating the OpenAPI document throws an `InvalidOperationException`. Use `WithErrorMetadata` to declare a contract inline for a single endpoint instead.

## Source generation

Mark a synchronous `Validator<T>` or `Validator<TSource, TValidated>` with `[GeneratePortableValidationOpenApi]` and make it `partial` to let the source generator produce an OpenAPI contract automatically from the validator's check calls. The generator ships with the `Light.PortableResults.Validation.OpenApi` package.

```csharp
[GeneratePortableValidationOpenApi]
public sealed partial class AddMovieRatingValidator : Validator<MovieRatingDto>
{
    public AddMovieRatingValidator(IValidationContextFactory validationContextFactory)
        : base(validationContextFactory) { }

    protected override ValidatedValue<MovieRatingDto> PerformValidation(
        ValidationContext context,
        ValidationCheckpoint checkpoint,
        MovieRatingDto dto
    )
    {
        context.Check(dto.Id).IsNotEmpty();
        dto.Comment = context.Check(dto.Comment).HasLengthIn(10, 1000);
        context.Check(dto.Rating).IsInRange(1, 5);
        return checkpoint.ToValidatedValue(dto);
    }
}

app.MapPut("/api/movieRatings", AddMovieRating)
   .ProducesPortableValidationProblemFor<AddMovieRatingValidator>(
        configure: x => x.UseFormat(ValidationProblemSerializationFormat.Rich)
    );
```

The generated part implements `IPortableValidationOpenApiContract`, whose static `ConfigurePortableValidationOpenApi(builder)` method applies the documented codes, metadata schemas, and examples to a `PortableValidationProblemOpenApiBuilder` — without reflection, so it also works with Native AOT. `ProducesPortableValidationProblemFor<TValidator>` applies the generated contract first and the optional `configure` callback second, so the callback appends endpoint-local codes, examples, or format overrides. Set `[GeneratePortableValidationOpenApi(AllowUnknownErrorCodes = true)]` to make the generated schema non-exhaustive.

### What the generator understands

The generator analyzes top-level `context.Check(...).Rule(...)` chains — including assignments such as `dto.Comment = context.Check(dto.Comment).HasLengthIn(10, 1000);` — and produces response schemas and examples from compile-time constants (for example, `HasLengthIn(10, 1000)` or `IsInRange(1, 5)`). Example messages use the targets and display names of the checks. It also reconstructs deterministic `DateTime`, `DateTimeOffset`, `TimeSpan`, `DateOnly`, `TimeOnly`, `Guid`, and `Uri` boundaries written with supported constructors, factories, well-known static values, or `static readonly` fields declared in the validator's file. Reconstructed message values and example metadata use the same canonical text.

Runtime-computed or unsupported boundary expressions still generate valid schemas, but the affected example omits its message and metadata and reports `LPRSG0015` at the argument. `DateTimeKind.Local`, culture-sensitive parsing, arithmetic or chained calls, and invalid constructor or factory arguments follow this degraded path. A `static readonly` field declared in another file or assembly is deliberately not followed and reports `LPRSG0016`; write the value inline or move its declaration into the validator's file when the complete example is required.

Checks inside control flow (`if` statements, loops, blocks), `Must(...)`, `Custom(...)`, assertions with `ErrorOverrides`, child validators, and errors added by hand are not inferred.

### Hints

Use `[PortableValidationOpenApiErrorHint]` to annotate codes the generator cannot infer (for example, from `Must(...)`, `Custom(...)`, or child validators):

```csharp
[GeneratePortableValidationOpenApi]
[PortableValidationOpenApiErrorHint("MovieAlreadyRated")]
public sealed partial class AddMovieRatingValidator : Validator<MovieRatingDto> { ... }
```

Hints can be placed on the validator class or on its `PerformValidation` method:

| Attribute | Purpose |
| --- | --- |
| `[PortableValidationOpenApiErrorHint(code)]` | Documents an additional error code, using the metadata contract registered for that code. |
| `[PortableValidationOpenApiErrorHint(code, typeof(TMetadata))]` | Documents an additional error code with an inline metadata type. |
| `[PortableValidationOpenApiErrorMetadataProperty(code, key, typeof(T))]` | Adds one property to the inline metadata schema of a hinted code. |
| `[PortableValidationOpenApiExampleHint(code, Target = ..., Message = ...)]` | Adds an entry for the code to the response example. |
| `[PortableValidationOpenApiExampleMetadata(code, key, value)]` | Adds a constant metadata value (string, integer, Boolean, floating-point number, or type) to an example entry. |

```csharp
[GeneratePortableValidationOpenApi]
[PortableValidationOpenApiErrorHint("RatingTooLow")]
[PortableValidationOpenApiErrorMetadataProperty("RatingTooLow", "lowerBoundary", typeof(int))]
[PortableValidationOpenApiExampleHint("RatingTooLow", Target = "rating", Message = "rating is too low")]
[PortableValidationOpenApiExampleMetadata("RatingTooLow", "lowerBoundary", 3)]
public sealed partial class PremiumRatingValidator : Validator<MovieRatingDto> { ... }
```

### MVC

MVC actions use attributes instead of callbacks. `[ProducesPortableValidationProblemFor<TValidator>]` applies the generated contract; its named properties such as `Format` override scalar settings:

```csharp
[HttpPut]
[ProducesPortableSuccessResponse<MovieRating>]
[ProducesPortableValidationProblemFor<AddMovieRatingValidator>(Format = ValidationProblemSerializationFormat.Rich)]
public async Task<LightActionResult<MovieRating>> AddMovieRating(MovieRatingDto dto) { ... }
```

Array properties such as `ErrorCodes` replace the generated values instead of appending to them. To append endpoint-local metadata, write a small contract type that implements `IPortableValidationOpenApiContract` and pass it as the second type argument. `TValidator` is applied first and `TEndpointContract` second, mirroring the order of the Minimal API callback:

```csharp
public sealed class AddMovieRatingEndpointContract : IPortableValidationOpenApiContract
{
    public static void ConfigurePortableValidationOpenApi(PortableValidationProblemOpenApiBuilder builder) =>
        builder
           .UseFormat(ValidationProblemSerializationFormat.Rich)
           .WithErrorCodes("MovieNotFound") // registered with contracts.ForCode<MovieNotFoundMetadata>("MovieNotFound")
           .WithErrorExample("MovieNotFound", "movieId", "There is no movie with the specified ID");
}

[HttpPut]
[ProducesPortableValidationProblemFor<AddMovieRatingValidator, AddMovieRatingEndpointContract>]
public async Task<LightActionResult<MovieRating>> AddMovieRating(MovieRatingDto dto) { ... }
```

The contract type can call every builder method that the Minimal API callback can: `UseFormat`, `WithMetadata`, `WithErrorCodes`, `WithErrorMetadata`, the typed validation helpers, `WithErrorExample`, and `AllowUnknownErrorCodes`.

## Documenting custom checks

The generator recognizes every assertion that is annotated like the built-in ones, so your own [custom assertions](validation/advanced.md#custom-assertions) can be documented as well:

```csharp
using Light.PortableResults.Validation;
using Light.PortableResults.Validation.Definitions;
using Light.PortableResults.Validation.Messaging;

public static class CustomChecks
{
    [ValidationRule("DivisibleBy", ErrorDefinitionType = typeof(DivisibleByDefinition))]
    [ValidationRuleMessage("{displayName} must be divisible by {divisor}")]
    [ValidationRuleMetadata("divisor", "divisor")]
    public static Check<int> IsDivisibleBy(this Check<int> check, int divisor)
    {
        // ... add an error created from DivisibleByDefinition when the value is not divisible
    }
}

[ValidationErrorContract("DivisibleBy")]
[ValidationErrorMetadataContract("divisor", typeof(int))]
public sealed class DivisibleByDefinition : ValidationErrorDefinition
{
    // ...
}
```

The attributes live in `Light.PortableResults.Validation.Definitions`:

- `[ValidationRule(errorCode)]` marks the method as a rule that emits `errorCode`. `MetadataShape` chooses how its metadata is documented: `Registered` (default; the contract registered for the code or declared by `ErrorDefinitionType`), `TypedComparison` (one `comparativeValue` of the checked type), or `TypedRange` (`lowerBoundary` and `upperBoundary` of the checked type). `ErrorDefinitionType` points to the definition that declares the contract.
- `[ValidationRuleMetadata(key, sourceArgument)]` binds a metadata key to a parameter of the method, so that examples contain the argument of the call site. The single-argument constructor with `ConstantStringValue`, `ConstantInt64Value`/`HasConstantInt64Value`, `ConstantBooleanValue`/`HasConstantBooleanValue`, or `ConstantTypeValue` binds a fixed value instead.
- `[ValidationRuleMessage(template)]` provides the example message. Placeholders are `{displayName}` and the metadata keys of the rule.
- `[ValidationErrorContract(errorCode)]` on a `ValidationErrorDefinition` declares that it produces a stable, documentable contract for that code, and `[ValidationErrorMetadataContract(key, typeof(T))]` describes each of its metadata properties.

<a id="diagnostics-reference"></a>

## Diagnostics reference

Every diagnostic links to its section below.

<a id="lprsg0001"></a>

### LPRSG0001: Validator must be partial

**Severity:** Error. A class marked with `[GeneratePortableValidationOpenApi]` is not `partial`, so the generator cannot add the `IPortableValidationOpenApiContract` implementation. Add the `partial` modifier.

<a id="lprsg0002"></a>

### LPRSG0002: Validator shape is not supported

**Severity:** Error. The marked class cannot receive generated code. The message names the reason: the class declaration could not be found, the validator is nested in another type, the validator is generic, or it does not inherit directly from `Validator<T>` or `Validator<TSource, TValidated>` (custom or indirect base classes are not supported). Move the validator to the top level of a namespace, remove its type parameters, or derive it directly from one of the supported base classes.

<a id="lprsg0003"></a>

### LPRSG0003: Async validators are not supported

**Severity:** Error. The marked validator derives from `AsyncValidator<T>` or `AsyncValidator<TSource, TValidated>`. Only synchronous validators are supported. Remove the attribute and document the endpoint with `ProducesPortableValidationProblem(...)` and explicit codes instead.

<a id="lprsg0004"></a>

### LPRSG0004: PerformValidation must be declared on the marked validator

**Severity:** Error. The marked class does not declare a synchronous `PerformValidation` override itself. Declare `PerformValidation` directly in the marked partial class.

<a id="lprsg0005"></a>

### LPRSG0005: Nested validation check was skipped

**Severity:** Warning. A `context.Check(...)` call is nested inside control flow such as an `if` statement, a loop, or a block. The generator only documents top-level statements, so the codes of this check are missing from the contract. Lift the check to a top-level statement, document its codes with [hints](#hints), or allow unknown error codes.

<a id="lprsg0006"></a>

### LPRSG0006: Opaque validation flow is not documentable

**Severity:** Warning. A call in a check chain cannot be inferred: `Must(...)` or `Custom(...)`, or a built-in assertion that receives `ErrorOverrides` and may therefore produce another code. Use an assertion that is annotated with `[ValidationRule]` (see [Documenting custom checks](#documenting-custom-checks)), add [hints](#hints), or allow unknown error codes.

<a id="lprsg0007"></a>

### LPRSG0007: Validation rule metadata is malformed

**Severity:** Error. A `[ValidationRuleMetadata]` attribute of the called rule binds a metadata key to a parameter that does not exist on the method or is not available at the call site. Fix the `sourceArgument` of the attribute so that it names a parameter of the rule method.

<a id="lprsg0008"></a>

### LPRSG0008: Validator produced no documentable validation rules

**Severity:** Info. The marked validator contains no check, hint, or rule that the generator could document, so the generated contract is empty. Add top-level checks or hints, or remove the attribute.

<a id="lprsg0009"></a>

### LPRSG0009: Validation error contract is malformed

**Severity:** Error. A rule's `ErrorDefinitionType` refers to a definition without a `[ValidationErrorContract]` attribute, or the attribute declares another error code than the rule. Annotate the definition with `[ValidationErrorContract]` using the code of the `[ValidationRule]`.

<a id="lprsg0010"></a>

### LPRSG0010: Validation OpenAPI hint is malformed

**Severity:** Error. A hint attribute is invalid. The message names the problem: an empty error hint, example hint, or metadata key; a `void` metadata or property type; an inline metadata property without a matching error hint in the same scope; example metadata without a matching example hint in the same scope; or more than one example hint for the same code in the same scope. A scope is either the validator class or its `PerformValidation` method.

<a id="lprsg0011"></a>

### LPRSG0011: Validation OpenAPI hint conflicts with another contract

**Severity:** Error. The documented metadata contracts of one code contradict each other: two error hints declare different metadata types, one hint declares both a metadata type and inline metadata properties, two hints declare different inline properties, or the inline properties of a hint differ from the metadata of a rule with the same code. Use one consistent metadata contract per code.

<a id="lprsg0012"></a>

### LPRSG0012: Validation OpenAPI example metadata is not declared by a schema hint

**Severity:** Warning. `[PortableValidationOpenApiExampleMetadata]` sets a key that no inline metadata schema of that code declares, so the example would not match the schema. Declare the key with `[PortableValidationOpenApiErrorMetadataProperty]` or remove the example value.

<a id="lprsg0013"></a>

### LPRSG0013: Validation rule message template has an unknown placeholder

**Severity:** Warning. A `[ValidationRuleMessage]` template contains a placeholder that is neither `{displayName}` nor a metadata key of the rule. The example message is omitted. Fix the placeholder name or add the corresponding `[ValidationRuleMetadata]`.

<a id="lprsg0014"></a>

### LPRSG0014: Validation rule message template is malformed

**Severity:** Warning. A `[ValidationRuleMessage]` template cannot be parsed, for example because of an unbalanced or empty brace. The example message is omitted. Fix the template syntax.

<a id="lprsg0015"></a>

### LPRSG0015: Validation metadata value cannot be reconstructed

**Severity:** Info. A metadata argument of a rule is not a compile-time constant or a supported deterministic expression, for example a value computed at runtime, a `DateTimeKind.Local` value, culture-sensitive parsing, arithmetic, chained calls, or invalid constructor or factory arguments. The schema is still generated, but the affected example omits its message and metadata. Use a constant or a supported constructor, factory, or `static readonly` field in the validator's file when the complete example matters.

<a id="lprsg0016"></a>

### LPRSG0016: Multi-file validation metadata field resolution is unsupported

**Severity:** Warning. A metadata argument refers to a `static readonly` field that is declared in another file or assembly. The generator deliberately does not follow such fields, so the example omits its message and metadata. Write the value inline or move the field declaration into the validator's file.
